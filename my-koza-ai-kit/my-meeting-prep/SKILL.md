# 面談準備（＋面談後の記録）

面談の**前**と**後**、両方で使うスキル。

- **準備モード**：面談前。その人の記録を集めて、当日のメモを1枚作る
- **面談後モード**：面談後。文字起こしを渡すと、約束・宿題・申し送りを抽出して記録する

**この2つが揃って初めて意味が出る。** 準備だけだと記録が溜まらず、2回目以降の準備が毎回ゼロからになる。

---

## ステップ0：初回セットアップ（初めて使うときだけ）

このスキルフォルダに `面談設定.md` が **無ければ初回**。以下を聞く。

### 0-1. どんな面談を、どのくらいやっているか ← まずここ

> 「まず教えてください。**どんな面談を、月に何回くらいやっていますか？**」

聞くこと：
- 面談の種類（例：受講生との個別Zoom／体験会／個別相談／初回オリエン）
- それぞれの頻度（月に何回）
- 1回あたりの時間
- **同じ人と繰り返し会うのか、毎回違う人か**

> 💡 **回数が少なくても、そのまま導入して問題ない。**
> むしろ回数が少ないうちに型を作っておくと、面談が増えたときにそのまま回る。
> それに、記録が溜まること自体が資産になる（2回目以降の準備が毎回ラクになる）。
> 「月に1回しかやっていない」でも、そのまま進めてよい。

### 0-2. 記録はどこにあるか
- 過去の面談メモ／議事録はあるか。どこにあるか
- Zoomの録画・文字起こしは残しているか
- 申し込みフォーム・アンケートの回答はどこにあるか
- チャット（LINE・メール等）のやりとりはどこにあるか

**「何も残していない」でも問題ない。** その場合は今日から溜め始める設計にする。

### 0-3. 面談の中身をヒアリングする ← ここが一番大事

**どんな面談なのかを知らないと、当日メモが的外れになる。** ここは丁寧に聞く。
AIから質問して担当者に答えてもらう形で進める。**「まとめて説明してください」と丸投げしない。**

聞くこと：

**① 面談の流れ**
- 最初に何を聞くか
- どう進めるか（相手に話してもらう時間が長いのか、こちらが提示するのか）
- どう終わるか（次回の約束をするのか、宿題を出すのか）

**② 毎回必ず確認していること**
定番の質問があれば挙げてもらう。無ければ一緒に3〜5個決める。

**③ 面談のゴール**
- 何が決まれば「今日はうまくいった」と言えるか
- 逆に、どうなったら「今日は失敗した」と感じるか

**④ よくある相談・つまずき**
- 相手からよく出る相談は何か
- 毎回同じことを説明している、ということはあるか（ここは後で型にできる）

> 💡 うまく答えられない項目があれば、AIが具体例を出して聞く。
> （「たとえば前回の宿題の確認から入りますか？それとも近況から入りますか？」のように）

### 0-4. 触れてはいけない話題があるか聞く

> 「面談で、この話題は避けたい／気をつけたい、ということはありますか？」

（例：他社の批判をしない／収益の保証をしない／特定の話題は本人から出るまで触れない）

### 0-5. フォルダを作る
```
<決めた場所>/面談/
├── 山田さん/
│   ├── カルテ.md            ← その人の基本情報・現在地（毎回更新）
│   ├── 2026-08-19_1回目.md  ← 各回の記録
│   └── 2026-08-24_2回目.md
└── 佐藤さん/
```

### 0-6. `面談設定.md` に保存する

```markdown
# 面談設定（my-meeting-prep）
最終更新：YYYY-MM-DD

## 面談の種類と頻度
-

## 記録の保存場所
- ルート：
- 過去の記録：
- 録画／文字起こし：

## 面談の中身（0-3のヒアリング結果）
- 流れ：
- ゴール（何が決まれば成功か）：
- よくある相談・つまずき：

## 毎回確認すること
-

## 触れないこと・気をつけること
-
```

# 準備モード（面談の前に使う）

## 1. 誰の面談か聞く
> 「どなたとの面談ですか？何回目ですか？」

## 2. 記録を全部集める
その人について、次を全部読む：
- `カルテ.md`
- 過去の面談記録（全部）
- 申し込み時のアンケート・フォームの回答
- チャットのやりとり
- （あれば）過去の録画の文字起こし

**初回の人で記録が無い場合**は、申し込み情報だけで作る。少なくてよい。

## 3. 当日メモを作る（この形で出す）

```markdown
# 面談メモ：◯◯さん（YYYY-MM-DD ／ ◯回目）

## 1. この人は今どこにいるか（30秒で読める長さ）
（現在地を数行で。数字があれば数字で）

## 2. 前回の約束・宿題
- [ ] 相手がやると言ったこと
- [ ] こちらがやると言ったこと ← ここを落とすと信頼を失う

## 3. 今日話すこと（優先順）
1.
2.
3.

## 4. 触れ方に注意すること
- （相手が気にしていること・過去に引っかかった話題）

## 5. 今日決めたいこと／次の宿題の候補
- （行動＋期日の形で。金額や成果の約束はしない）
```

### 作るときの原則
- **「こちらがやると言ったこと」を必ず拾う。** 相手の宿題より優先して確認する
- 記録に無いことを推測で書かない。**「記録からは不明・当日確認」と明記する**
- 話すことは**3つまで**に絞る。多いと全部浅くなる

## 4. 渡す
> 「面談メモです。**2番の『前回の約束』だけは、始まる前にもう一度見てください。**」

# 面談後モード（面談が終わったあとに使う）

## 1. 素材を受け取る
文字起こし・録画・手書きメモ、何でもよい。無ければ担当者に口頭で振り返ってもらう。

## 2. 次を抽出する

```markdown
# ◯◯さん YYYY-MM-DD（◯回目）

## 決まったこと
-

## 相手の宿題（次回まで）
- [ ]

## こちらの宿題（次回まで）  ← 必ず分けて書く
- [ ]

## 新しく分かったこと
- （前提が変わった／数字が変わった／状況が変わった）

## 準備メモの答え合わせ
- 当たっていたこと：
- 外れていたこと：   ← ここを残すと次回の精度が上がる

## 次回への申し送り
-
```

### 特に注意して拾うこと
- **「次回◯◯します」という自分の発言**（一番忘れやすく、一番信頼に響く）
- 相手が言った**期日**
- 相手の**温度が上がった瞬間／下がった瞬間**とその話題
- 事前の想定と実際が**違っていた点** ← これが次回の準備の質を決める

## 3. 保存する
1. その回の記録を `YYYY-MM-DD_◯回目.md` として保存
2. **`カルテ.md` を更新する**（現在地を今の状態に書き換える。過去分は下に残す）

> ⚠️ **カルテの更新を飛ばさない。** ここを飛ばすと、次回の準備でまた全部読み直すことになる。

---

## やらないこと

- 記録に無いことを推測で書かない
- 相手に無断で録画・文字起こしをしない（**録画の許可は担当者が取る**）
- 面談メモに、相手に見せられない書き方をしない（万一共有しても問題ない表現にしておく）
- 成果や金額の約束を提案に含めない（宿題は「行動＋期日」の形にする）
- 既存の記録を削除・上書きしない（追記と新規作成）

## 困ったとき

| 症状 | 対処 |
|---|---|
| 過去記録が何も無い | 今回から溜め始める。初回は申し込み情報だけで作れば十分 |
| 文字起こしが無い | 担当者に口頭で振り返ってもらい、それを記録にする。5分話してもらえば十分作れる |
| 準備メモが毎回外れる | 「答え合わせ」の欄を必ず書く。3回も溜まれば当たるようになる |
| 面談が多すぎて準備が回らない | 全員分やらない。次に会う3人分だけ作る |
| 面談の回数が少ない | そのまま使ってよい。少ないうちに型を作っておくと、増えたときにそのまま回る。記録が溜まること自体が資産になる |
